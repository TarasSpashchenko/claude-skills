# Profile: sdlc-factory (knowledge-foundation)

Read this when the docs under review were generated by the `knowledge-foundation` skill of **sdlc-factory** (the `ai-packages/sdlc-factory` package of `codemie-public-skills`), or are read by its delivery agents. Everything here was read in that package in November 2026; the package changes fast, so check each line number and command in the revision you export before you put it in a prompt.

## What the generator produces

- `AGENTS.md`: the entry point, loaded into every session; `CLAUDE.md` holds `@AGENTS.md`. Its tables sit in marker blocks `<!-- ai-run-init:<block> start -->` … `end -->`: `guide-imports` (the guide table), `task-classifier` (Task Routing: category, intent, example requests, P0 guide, P1 guide), `critical-rules`, `commands` (Commands Routing), `behavioral-defaults`. Text outside the blocks is the user's and survives a run.
- `.ai-run/guides/**`: the guides, plus `.ai-run/guides/README.md` (the guide index) and `.ai-run/guides/knowledge-manifest.json` (`last_updated` stamps the run).
- Loading rule an agent follows: match the request to a Task Routing row and load its **P0** guide ("Check Guides First" in Critical Rules). P1 is optional; a task whose answer sits only in the P1 guide is at risk.

`kit.py` defaults (`--docs AGENTS.md CLAUDE.md .ai-run`, `--guides .ai-run/guides`, `--route-col 'P0( guide)?'`, headings below, caps 400/300) fit this profile.

## The contract

`skills/knowledge-foundation/references/knowledge-craft.md`:
- the generated sections of a guide: `## Overview` (two or three sentences, then at most 15 `Part | What it holds | Start here` rows), `## Key abstractions`, `## Examples` (per pattern a `### <name>`, a `Source: \`path::Symbol\`` line and a fence of **at most 20 lines copied verbatim, complete**), `## Common pitfalls` (`Symptom | Cause | Fix | Evidence`), `## Quick reference` (three or more `Task | Do | Where` rows, none repeating a rule). The guide index has none of them. Each section is kept when the code gives it content and deleted when it does not.
- caps: 400 lines per guide, 300 for the entry point (soft).
- a behaviour claim in an Overview or a pitfall row passes the same admission tests as a rule.

Find the lines with `grep -n '## Overview\|400 lines\|300 lines' <generator>/skills/knowledge-foundation/references/knowledge-craft.md` and cite them as `file:line` in the prompt.

## The checker

Run from the root of each set: `sh <generator>/scripts/sdlc-guides check > <root>/facts/check-<L>.txt`.

- Prints `status: ok | fail` and counters. **Exit 1** when `over_cap + broken + placeholders + run_artifacts + excerpt_drift + doc_drift > 0`; `drifted`, `legacy`, `unanchored`, `gate_as_test` and `untested_exemplar` are warnings (read in the script's header; confirm in your revision).
- Diagnostic lines start with their counter name (`unanchored: …`, `unknown_name: …`, `fence_drift: …`, `doc_drift: …`, `legacy: …`). Count them with `grep -c '^<name>:'`, never including the summary.
- `fence_drift` is an Examples fence line the source no longer holds; `doc_drift` a pointer to a document heading that is gone; `legacy` an old `path:line` anchor.
- The checker sees anchors and fences. It does not see a false behaviour claim, a wrong-guide route, a rule inserted inside a table, or a duplicate routing phrase: those are the reviewers' job.

**Which revision.** Run the checker of the newest generator revision, and say so. The revision that produced the set is usually older: take the manifest's `last_updated` stamp and the last generator commit before it (`git log --until=<stamp> -1`), and call it inferred, since the run directory is not in the repository.

## Defect families seen in past runs

Look for these in every set; each was found in more than one run:

1. Inherited false text survives regeneration: existing guides are "verified" through edits by default (`planning.md`), and a line without an edit stays.
2. New true text added beside contradicted old text (a fresh Overview that contradicts the body), or old text deleted leaving empty headings and half tables.
3. Examples fences cut at 20 lines mid-body, so the excerpt is not complete.
4. Quick-reference tables inserted after `---` with no header row; a rule block inserted inside a table.
5. In `AGENTS.md`, the old catch-all routing row kept beside the new specific rows, so one example phrase routes to two P0 guides; guides in no routing row; the guide index not regenerated and not routed.
6. Universal claims written without checking every branch of the code ("every request …", "rejects with …").
7. Overview and Quick reference repeating the guide body.
8. Useful lessons dropped when a section was rewritten.
9. Paths with the wrong letter case (they resolve on macOS, not on Linux).
10. Rules with no source, and examples that break the guide's own rule (a commit-subject example longer than the stated limit).
