# Agent harnesses: folder access and shell limits

Use this when you write a prompt or a hand-off line for an agent harness. It answers two questions: how the user starts the harness so it can write to the discussion folder, and how long its shell lets one command run. The `wait` command of `board.py` runs for up to 540 seconds and prints nothing until it ends.

Harnesses change quickly. Everything here was read in official docs on **2026-10-27**. Before you quote a flag, check the installed tool's `--help` or its docs if they may have changed, and update this file. When a flag is uncertain, the safe instruction is always "start the session inside the discussion folder". The participant's first-step capability test (`group-mode.md` §10) catches whatever the docs miss.

| Harness | How the user gives it the folder | Shell time limit | Notes |
|---|---|---|---|
| Codex CLI (`codex`) | `codex -s workspace-write --add-dir <dir>` (write access next to the workspace), or `codex -s workspace-write -C <dir>` to work in it. `-s workspace-write` (`--sandbox`) makes sure the session may write at all | A one-shot command ends after 10 s unless the call sets `timeout_ms` (repository source, `exec_command.rs`) | Tell it to give each `wait` call `timeout_ms: 600000`. `--add-dir` has no effect under the `read-only` sandbox. Writes outside the workspace need approval. |
| Claude Code (`claude`) | `claude --add-dir <dir>`, or `/add-dir <dir>` in a running session | Bash defaults to 120 s, at most 600 s | Tell it to give each `wait` call `timeout: 600000`. |
| GitHub Copilot CLI (`copilot`) | `copilot --add-dir=<dir>`, or `copilot -C <dir>`, or `/add-dir` | No documented limit | `--add-dir` also loads `.github/skills` and `.github/agents` from that folder as trusted. Writes outside the working folder ask for approval. |
| opencode (`opencode`) | Start it in the folder: `opencode <dir>` (positional project). There is no add-dir flag | Bash defaults to 120 s (repository source), with a per-call `timeout` | Access outside the project goes through the `permission.external_directory` rule. Its default differs between versions, so prefer starting in the folder. Tell it to set a per-call timeout above 540 s, or to lower `--timeout`. |
| pi (`pi`) | `cd <dir> && pi`. There is no folder flag | Not documented | It has no sandbox: tools run with the user's own permissions. The npm package moved to `@earendil-works/pi-coding-agent`. |
| Antigravity CLI (`agy`) | Start it in the discussion folder and add the source folders: `cd <dir> && agy --add-dir <src>` (repeatable; in `agy --help` of v1.5.3, checked 2026-11-08) | Not documented | Under the Default preset, commands run in a sandbox that reaches only the workspace and temp folders, with no network. Start it in a parent folder when it must also read sibling repositories. Tell it to use `--timeout 240`, because the limit is unknown. |
| Gemini CLI (`gemini`) | `gemini --include-directories <dir>` (comma list, at most 5), or start it in the folder | A command ends after 300 s with no output (`tools.shell.inactivityTimeout`) | `wait` prints nothing while it waits, so tell it to use `--timeout 240`. The docs say "added to the workspace" and don't state write access, so rely on the capability test. |

Sources: [Codex CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference), [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference), [Claude Code environment variables](https://code.claude.com/docs/en/env-vars), [Copilot CLI command reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference), [opencode CLI](https://opencode.ai/docs/cli), [opencode permissions](https://opencode.ai/docs/permissions), [pi CLI](https://pi.dev/docs/latest/cli), [pi security](https://pi.dev/docs/latest/security), [Antigravity permissions](https://antigravity.google/docs/cli/permissions), [Gemini CLI configuration](https://github.com/google-gemini/gemini-cli/blob/main/docs/reference/configuration.md), [Gemini CLI shell tool](https://github.com/google-gemini/gemini-cli/blob/main/docs/tools/shell.md).

A harness that isn't listed: ask the user how they start it, or tell them to start it inside the discussion folder. A chat app or a person with no file access takes part by relay.
